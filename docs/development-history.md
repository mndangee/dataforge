# DataForge 개발 과정

DataForge는 단순 JSON 응답 도구에서 시작해, 실제 프로젝트의 요청 주소를 바꾸지 않고도 모의 응답과 실제 서버를 함께 사용할 수 있는 데스크톱 프록시로 발전했습니다.

이 문서는 완성된 기능만 나열하지 않고, 개발 과정에서 어떤 문제를 발견하고 구조를 개선했는지 기록합니다.

## 1. 프록시와 데이터 관리 기반

- Electron과 React로 로컬 데스크톱 애플리케이션 구성
- 프로젝트와 API별 JSON 응답 저장 구조 설계
- Default, Test, Error 응답 분류와 활성 응답 선택 기능 구현
- 저장된 응답이 없을 때 실제 프로젝트 서버로 전달하는 프록시 흐름 구성

## 2. 기존 프로젝트와의 연결

- 클라이언트 요청 주소를 변경하기 어려운 환경을 위해 포트 전환 방식 도입
- 실행 중인 프로젝트 서버를 이동 포트에서 다시 실행하고 원래 포트를 프록시가 사용하도록 구성
- 정상 종료와 비정상 종료 후 서버 복구 상태를 디스크에 기록
- Node.js 버전 차이와 실행 명령 감지 오류를 사용자 진단 메시지로 안내

## 3. 더미 데이터 가져오기 개선

- JSON 파일, 폴더, ZIP 가져오기 지원
- 파일명과 JSON 본문에서 트랜잭션 정보를 분석
- API 메타데이터 파일에서 이름과 설명을 자동 연결
- 빈 파일, 깨진 JSON, 과도하게 큰 파일과 지원하지 않는 구조 검증
- 동일 파일 재가져오기에서 추가·업데이트·건너뜀·실패 결과를 구분
- 일부 파일이 실패해도 정상 데이터는 유지하는 부분 성공 처리

## 4. 응답 선택과 편집 경험

- JSON 편집 내용 저장과 활성 응답 적용을 하나의 흐름으로 통합
- URL 쿼리 조건별 응답 선택 기능 추가
- 조건이 일치하지 않을 때 사용자가 선택한 기본 응답으로 폴백
- 최근 요청에서 트랜잭션 ID, API 이름, 응답 종류와 처리 시간을 확인
- 최근 요청에서 해당 API 상세 화면으로 바로 이동

## 5. 운영체제 호환성과 배포

- Windows 파일·폴더 선택과 내부 페이지 이동 문제 수정
- Windows 프로세스 이름 충돌과 설치 프로그램 종료 감지 문제 수정
- macOS 서명 전 테스트를 위한 `open.mac.command` 배포 방식 제공
- Windows와 macOS 결과물을 함께 생성하는 릴리즈 절차 구성
- 앱 시작 시 흰 화면 대신 로딩 화면을 표시해 실행 상태를 명확하게 개선

## 6. 보안과 범용화

- Electron preload와 IPC 노출 범위를 명시적으로 제한
- 패키지 취약점 점검과 의존성 업데이트
- 프로젝트 전용 명칭과 경로를 범용 API 메타데이터 구조로 변경
- 배포 패키지에서 개발 문서, 스크립트와 소스 원본 제외
- 문서와 예시를 가상의 `DEMO.API0001` 형식으로 통일

## 검증 방식

- TypeScript 타입 검사
- Electron 프로덕션 빌드
- Windows x64 설치 파일 생성
- macOS ARM64 unsigned ZIP 생성
- 실제 프록시 연결, 응답 선택과 서버 복구 수동 시나리오
- 배포 패키지 내부 파일과 공개 금지 문자열 검사

전체 세부 변화는 Git 커밋 이력에서 기능별로 확인할 수 있습니다.
